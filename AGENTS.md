# EasyHybrid4 Codex instructions

Before **every** coding session, read `docs/ROADMAP.md` in full. Treat it as the authoritative task queue. Read `docs/EASYHYBRID4_REPORT.md` for consolidated repository, compatibility, test, and limitation status. Select the next eligible unchecked task, work incrementally, add tests, run only tests you can actually execute, and record OS/architecture and exact GTK runtime versions in the roadmap evidence log. Never claim Linux tests prove macOS/Windows support. Do not mark a task complete unless its acceptance criteria pass. Preserve scientific calculations, project compatibility and published graphics submodule reachability. Update the roadmap and consolidated report before ending.

**Native GTK acceptance:** before merging an implementation to `main`, run the full `.github/workflows/native-gtk-matrix.yml`: Linux x86_64, Windows x86_64 and macOS arm64 for every released GTK4 minor from 4.8 through the supported latest; also Intel macOS cells where provisioned. The matrix must run the EasyHybrid menu/VisMol scene through two open/render/close cycles per cell. Read the uploaded runtime artifact and confirm the actual GTK patch version, OS/architecture, Python, PyGObject and GL backend; a green job or requested matrix label alone is not version evidence. Physical GPU, Retina, trackpad and Wayland results remain separate claims.

**Failure protocol:** inspect the first failing assertion/native stack and the affected job's uploaded runtime log before starting another run. Identify whether it is application code, GTK/backend behavior, test setup or missing dependency; make one focused correction, run the smallest relevant check once, then run the full matrix once. Do not launch overlapping or repeated matrices, rerun passing cells, or push a test-only retry before understanding the failure. If CI fails, fix that failure and rerun the failed coverage in the same work sequence before adding more checks.

**Known GTK CI traps (verified 2026-10-19):** GTK 4.16/4.18 Linux distro builds use EGL on X11 even when `GDK_DEBUG=gl-glx` is requested; do not force PyOpenGL GLX for the EasyHybrid scene. Fedora's optional `OpenGL_accelerate` may have a NumPy ABI mismatch; its scene smoke uses PyOpenGL's ctypes path. Windows async native COM file-dialog cancellation can disconnect GTK's callback apartment and crash GLib iteration; keep the tested in-process chooser policy and fatal-exception log guard. GTK 4.8/4.10 Windows needs the legacy WGL pixel-format adapter. `setup-micromamba@v3.2.1` using its unpinned latest micromamba lookup transiently failed on 2026-10-19 (it reported no `linux-64` binary for `2.9.0-0`, although the asset exists; its post-cleanup JSON error was secondary). The workflow pins `2.9.0-0`; do not pin below 2.9.0, because micromamba 2.8.x rejects the Windows GTK 4.8/4.10 `--skip-run-link-scripts` create flag (run `39278528559`). Environment-cache hits hide installer regressions: any `create-args` change re-runs `create`. The latest full main matrix run `39275185493` passed all 30 cells, including two real scene render/close cycles in each cell. pDynamo3 scientific tests are separate and must run against the pDynamo3 environment.
